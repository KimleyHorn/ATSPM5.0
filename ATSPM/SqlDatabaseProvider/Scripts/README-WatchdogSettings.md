# WatchDog settings rollout (SQL Server)

1. Back up the ATSPM5 **configuration** database. ConfigApi does **not** migrate by default: set `DatabaseConfiguration:ConfigContext:RunMigrations` to `true` for one ConfigApi startup (for example, set `DatabaseConfiguration__ConfigContext__RunMigrations=true` in that process's environment), then restart ConfigApi. Check its logs for migration errors: ConfigApi currently logs migration failures but can still start, so "Application started" is not proof that migration succeeded. The migration creates `dbo.WatchdogSettings` and seeds row `Id = 1` with the ATSPM4 ApplicationID 2 scan settings. You may turn the flag off again afterward.
2. Verify with `SELECT MigrationId FROM dbo.__EFMigrationsHistory WHERE MigrationId = '20261007000000_WatchdogSettings'; SELECT * FROM dbo.WatchdogSettings WHERE Id = 1;` against the **same** configuration database used by ConfigApi. Do not run `SeedWatchdogSettings.sql` until the table exists. The script is an idempotent fallback if the row is missing; it never overwrites UI edits.
3. Start the updated WebUI and open **Admin → Watchdog Settings**. A user needs `GeneralConfiguration:View` to see the page and `GeneralConfiguration:Edit` to save it. The page can report overrides visible to ConfigApi; independently deployed WatchDog processes may have additional overrides.
4. Keep database connection strings and SMTP host/credentials in appsettings or the environment. Remove only the `WatchdogConfiguration` keys that should be controlled by the database from WatchDog's appsettings files, environment variables, and user secrets. Any explicitly present key wins over the saved value; command-line options win for that scan.
5. Restart WatchDog (or run its `generate` command) to use the settings. For a MailHog test, configure its SMTP connection to `localhost:1025`, assign at least one user with an email address to `WatchdogSubscriber`, ensure the configuration database has active locations and data for the scan date, then inspect `http://localhost:8025`. Sending is conditional on detected errors; saving settings alone does not send a message.

The ATSPM4 `FromEmailAddress` maps to ATSPM5 `DefaultEmailAddress` (the sender). The old `DefaultEmailAddress` recipient does **not** map to that field; ATSPM5 recipients come from subscriber users. One-off scan dates remain command-line/configuration options and are not exposed in the settings page.

This migration targets SQL Server. Other database providers need their own migrations before this feature can be used with them.
